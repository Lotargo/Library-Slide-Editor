# Roadmap: Library Project Evolution

Этот документ описывает стратегический план развития проекта **Library**, фокусируясь на производительности, внедрении AI-агентов и построении графов знаний.

---

## 🎯 Стратегические Цели

1.  **Производительность:** Обеспечить плавную работу со страницами, содержащими 1000+ блоков (виртуализация).
2.  **AI-Оркестрация:** Создать надежную среду ("Триада") для работы LLM-агентов, исключающую галлюцинации в логике управления.
3.  **Граф Знаний:** Реализовать "второй мозг" с визуализацией связей и семантическим поиском.
4.  **Командная Работа:** Внедрить Real-time Collaboration без конфликтов.
5.  **Инфраструктура:** Полная контейнеризация (Docker) с поддержкой кастомных сценариев управления.

---

## 🏗 Архитектурные Паттерны (Architecture Patterns)

Для сохранения чистоты кодовой базы применяется принцип разделения ответственности ("Триада Типизации").

### 1. 🟢 Полная Триада (TS + Pydantic + PowerShell)
**Зона ответственности:** "Руки Агента", Сложные Операции, Оркестрация.
*Где применять:*
*   **AI Tools / Skills:** Агент выполняет сложные действия (создать отчет из JIRA, проанализировать Git-репозиторий).
*   **ETL Pipeline:** Импорт/экспорт данных, миграции графа, сложные трансформации.
*   **DevOps:** Управление инфраструктурой, бэкапы, системные чеки.
*   *Принцип:* TS задает контракт (интент), Pydantic валидирует входные параметры, PowerShell (в Docker) выполняет изолированный скрипт.

### 2. 🟡 Связка TS + Pydantic (Python Native)
**Зона ответственности:** API Контракты, Обмен данными, Быстрые операции.
*Где применять:*
*   **Client-Server API:** Стандартные запросы фронтенда (создать блок, обновить текст).
*   **Structured Outputs (LLM):** Валидация JSON-ответов от LLM (классификация, извлечение сущностей).
*   **OpenAI Client:** Клиент пишется на Python для нативной интеграции с Pydantic. Переписывание на Rust нецелесообразно (нет CPU-нагрузки, но сложнее маппинг типов).

### 3. 🔵 Только TypeScript
**Зона ответственности:** UI/UX, Визуализация, Клиентское состояние.
*Где применять:*
*   **State Management:** Активный слайд, открытые меню, фокус.
*   **Interaction Logic:** Drag-and-drop, ресайз, выделение текста.
*   **Frontend CRDT (Yjs):** Клиентская часть синхронизации.

### 4. 🔴 Anti-patterns (Где Триада НЕ нужна)
*   **Simple CRUD:** Простые операции чтения/записи (Get Users) не требуют скриптов.
*   **High-Frequency Loops:** Обработка тысяч элементов в реальном времени (Real-time collab) должна идти на нативном коде (Rust via PyO3).

## 🗺 Этапы Развития (Phases)

### Phase 1: Core Optimization (Frontend Virtualization)

*Проблема:* Рекурсивный рендеринг блоков (`BlockList` внутри блоков) создает глубокое DOM-дерево.

**Решение: Flat State Architecture**
1.  **Рефакторинг Стейта:** Переход к нормализованной структуре `{ blocks: { [id]: BlockData }, pageLayout: [...] }`.
2.  **Виртуализация:** Внедрение `react-window` или `react-virtuoso`.

### Phase 2: AI Orchestration & Data Integrity ("The Triad")

*Концепция:* Обеспечение "контрактного рассуждения".

**Архитектура "Триада":**
1.  **TypeScript:** Описывает онтологию графа.
2.  **Pydantic:** Бэкенд-валидация и гарантия структуры данных.
3.  **PowerShell:** Оркестрация "тяжелых" процессов в Docker.

### Phase 3: Knowledge Graph Data Layer

*Вопрос:* Как хранить сложный граф?

**Гибридная схема (Hybrid Storage):**
*   **MongoDB:** Узлы и явные связи (Hard Links). Валидация целостности.
*   **Qdrant:** Векторный поиск и семантические связи (Soft Links).

### Phase 4: Graph Visualization (Rust & WebAssembly)

*Задача:* Рендеринг графов (2D/3D).

**Технологический стек:**
1.  **Engine:** Rust-библиотеки (через WASM) для Force-directed layout.
2.  **Rendering:** WebGL (библиотеки типа `cosmograph` или `force-graph`).

### Phase 5: Integrations & Generic LLM Gateway

1.  **Generic OpenAI Client:** Универсальный Python-клиент (поддержка `OPENAI_BASE_URL`).
2.  **Testing Strategy:** Использование **Cerebras** (OpenAI-compatible) для тестов.

### Phase 6: Real-time Collaboration (Rust + CRDT)

*Задача:* Позволить нескольким пользователям редактировать страницу одновременно.

**Гибридная Архитектура (Python + Rust):**

1.  **Frontend:** Библиотека **Yjs**.
    *   Стандарт де-факто для CRDT в браузере.
    *   Работает с текстом, массивами (блоки) и картами.
2.  **Backend Integration (Rust via PyO3):**
    *   *Проблема:* Чистый Python медленно работает с CRDT-алгоритмами при высокой нагрузке.
    *   *Решение:* Использование **Rust** модуля (через `PyO3` / `Maturin`).
    *   **Logic:**
        *   Django (Channels) держит WebSocket соединение и проверяет права (Auth).
        *   Полученный бинарный патч передается в Rust-функцию.
        *   Rust (библиотека `y-crdt`) применяет патч к документу в памяти и возвращает результат.
    *   *Преимущество:* Мы не поднимаем отдельный Rust-микросервис, а встраиваем производительность Rust прямо в Django.
