# Roadmap: Library Project Evolution

Этот документ описывает стратегический план развития проекта **Library**, фокусируясь на производительности, внедрении AI-агентов и построении графов знаний.

---

## 🎯 Стратегические Цели

1.  **Производительность:** Обеспечить плавную работу со страницами, содержащими 1000+ блоков (виртуализация).
2.  **AI-Оркестрация:** Создать надежную среду ("Триада") для работы LLM-агентов, исключающую галлюцинации в логике управления.
3.  **Граф Знаний:** Реализовать "второй мозг" с визуализацией связей и семантическим поиском.
4.  **Инфраструктура:** Полная контейнеризация (Docker) с поддержкой кастомных сценариев управления.

---

## 🗺 Этапы Развития (Phases)

### Phase 1: Core Optimization (Frontend Virtualization)

*Проблема:* Рекурсивный рендеринг блоков (`BlockList` внутри блоков) создает глубокое DOM-дерево, что делает невозможным использование эффективной виртуализации списка при большом количестве элементов.

**Решение: Flat State Architecture**

1.  **Рефакторинг Стейта (Redux/Zustand):**
    *   Переход от вложенной структуры JSON к нормализованной (плоской).
    *   Стейт: `{ blocks: { [id]: BlockData }, pageLayout: [id1, id2, ...] }`.
    *   Вложенность (например, внутри слайдов) реализуется через ссылки `childrenIds` в родительском блоке, но рендеринг остается "плоским" с точки зрения React-дерева или управляется виртуализированными списками внутри контейнеров.
2.  **Виртуализация:**
    *   Внедрение `react-window` или `react-virtuoso`.
    *   Рендеринг только видимых в viewport блоков.
    *   Поддержка динамической высоты блоков (измерение `ResizeObserver`).

### Phase 2: AI Orchestration & Data Integrity ("The Triad")

*Концепция:* Обеспечение "контрактного рассуждения" для RAG и агентов.

**Архитектура "Триада":**

1.  **TypeScript (Mental Model):**
    *   Описывает онтологию графа: `Node types`, `Edge types`, `Rules`.
    *   Фронтенд и AI-клиенты используют эти типы как "закон" о том, какие связи допустимы.
2.  **Pydantic (Validation Layer):**
    *   Бэкенд-валидация всех входящих/исходящих данных от LLM.
    *   Гарантия структуры: `Entity` всегда имеет типизированные поля.
    *   Фильтрация "галлюцинаций" на входе в БД.
3.  **PowerShell (Execution Orchestrator):**
    *   **Роль:** Управление процессами RAG, индексацией, обслуживанием графа.
    *   **Интеграция:** Установка `pwsh` (PowerShell Core) в Docker-контейнер бэкенда.
    *   **Сценарии:** Скрипты для пакетной обработки, ре-индексации векторов, очистки устаревших связей. Агент вызывает скрипт, а не выполняет сырые команды.

### Phase 3: Knowledge Graph Data Layer

*Вопрос:* Как хранить сложный граф?

**Гибридная схема (Hybrid Storage):**

*   **MongoDB (Structure & Truth):**
    *   Хранение узлов (Pages, Blocks) и явных ребер (Links).
    *   "Жесткие" связи, созданные человеком.
    *   Валидация целостности ссылок.
    *   *Почему не Neo4j сейчас:* Для текущих задач навигации и RAG возможностей MongoDB (+ $graphLookup) достаточно. Neo4j добавляется как отдельный слой только при необходимости сверхсложных аналитических запросов (Deep Traversal).
*   **Qdrant (Semantic Layer):**
    *   Векторное хранилище для текстового контента.
    *   "Мягкие" связи: поиск по смысловой близости (Nearest Neighbors).
    *   Используется для RAG (Retrieval Augmented Generation).

### Phase 4: Graph Visualization (Rust & WebAssembly)

*Задача:* Рендеринг графов (2D/3D) с тысячами узлов без лагов.

**Технологический стек:**

1.  **Engine:** Использование Rust-библиотек (через WASM) для вычисления Layout (Force-directed algorithms).
    *   Это выносит тяжелые вычисления физики графа из JS-потока.
2.  **Rendering:** WebGL (через библиотеки типа `cosmograph` или `force-graph`, имеющие WASM-модули).
3.  **UX Modes:**
    *   **Global View:** Полноэкранный режим исследования базы знаний.
    *   **Graph Block:** Embed-компонент для вставки локального графа контекста на страницу.

### Phase 5: Integrations & LLM Gateway

1.  **OpenAI Standard Protocol:**
    *   Реализация клиента на бэкенде, умеющего работать с любым OpenAI-совместимым API (Ollama, LM Studio, vLLM, OpenAI).
    *   Настройка `Base URL` и `API Key` пользователем.
2.  **External Integrations:**
    *   Google Docs / Sheets, Jira, Git.
    *   Импорт данных в граф знаний через коннекторы (PowerShell скрипты для ETL).
